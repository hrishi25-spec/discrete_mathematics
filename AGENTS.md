HARD RULES
1. Work ONLY from the source files plus standard, well-established mathematics. Never invent course content. If a topic appears in the practice questions but not in the slides (e.g. Havel-Hakimi, vertex/edge connectivity kappa and kappa', colour-critical graphs, hash-collision/birthday approximation), mark it "Not in slides - standard result" and still cover it.
2. The slides contain typos. Known examples: induction written as "for all k>1" (should be k>=1); strong induction "1<t<k" (should be 1<=t<k); AM-GM stated for "distinct reals" (needs a,b>=0); Q9(a) in questions.pdf says x_i>1 while the markdown version says x_i>=1; the slide on quantifiers uses a biconditional where an implication is meant. Correct these silently in the guide, and list each one in a "Slide errors I fixed" box.
3. Every numerical answer (counting, recurrences, probabilities, partitions, MST weights, etc.) MUST be verified by running a short Python script (brute force or independent formula) BEFORE you write it into the HTML. If the check fails, fix it. Never guess a number.
4. Every theorem listed in the slides gets a COMPLETE proof, written in steps, not just a sketch.
5. No real images can be generated. For every "picture, diagram, graph, flowchart, animation" use only: inline SVG, HTML canvas, CSS animation, or vanilla JavaScript. No external images. No CDN dependencies, so everything works offline. Use real drawn diagrams (graphs with vertices/edges, Ferrers diagrams, lattice paths, trees, Venn diagrams, flowcharts of algorithms), not decorative ones.
6. Math must render offline. Use clean HTML/Unicode math (x^2, C(n,k), sums written clearly). If you use KaTeX or MathJax, vendor the files locally into the folder; do not link a CDN.
